# Integration matrix

Each adapter declares a status: `disabled`, `manual`, `sandbox`, `connected`, `degraded`, `blocked`. Status is stored in `integration_settings` and shown on `/integrations`. No live integration is simulated; the manual route is always fully functional.

| Provider                     | Status         | Available now                                                                                                                             | Not available                      | Before enabling                                                                                                          |
| ---------------------------- | -------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| JoinedUp                     | manual         | Entry queue: record booking ID, verify with evidence, mark discrepancy, verify cancellation; out-of-date detection when the shift changes | API writes, compatible import file | Provider documentation, sandbox, field mapping, ownership per field, duplicate/amend/cancel tests                        |
| WhatsApp                     | disabled       | Paste incoming messages; copy drafts and record manual sends                                                                              | Sending, reading groups            | Business number, Groups API eligibility on the actual account, templates, consent policy, webhook signature verification |
| Email                        | manual         | Paste email text as a source                                                                                                              | Mailbox ingestion                  | Provider choice (Microsoft 365 / Google / other), scoped mailbox permissions, subscription renewal and backfill          |
| AI extraction                | disabled       | Not needed for any workflow                                                                                                               | Proposals from messages            | Data-processing approval, cost limits, evidence-span validation, review UI                                               |
| Transactional email (Resend) | not configured | Supabase auth emails via provider SMTP                                                                                                    | Notifications                      | Domain verification and provider terms                                                                                   |
| Maps/routing                 | not configured | Verified pins entered by staff; travel minutes entered by dispatcher                                                                      | Geocoding, route optimisation      | Cost/licence/data review (P3)                                                                                            |

A provider send always goes through the outbox: the draft is checked for currency (revision, contact, assignment state) and marked `delivery_unknown` before the call. Timeouts never trigger an automatic resend.

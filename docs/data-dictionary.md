# Data dictionary

All tables live in the `app` schema (`packages/db/src/schema.ts`). Common columns: UUID `id`, `organisation_id` (all organisation-owned rows), `created_at/by`, `updated_at/by`, `version` (optimistic concurrency). Instants are `timestamptz`; service dates are `date` strings (`YYYY-MM-DD`); local times are `time` with an explicit `timezone`.

| Table                                                                                                           | Purpose                                                                                                                                                                |
| --------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| organisations, branches                                                                                         | Tenant and branches; `settings` JSON holds configurable operating policy                                                                                               |
| memberships, branch_memberships                                                                                 | Staff linked to verified auth users; organisation and branch roles                                                                                                     |
| duty_periods                                                                                                    | Who covers a branch when, with backup                                                                                                                                  |
| clients, client_contacts, sites, work_locations, site_aliases                                                   | Legal client, operational site, verified entrances/fields (`verified_at`)                                                                                              |
| readiness_requirements, readiness_checks                                                                        | Configured requirements (scope, blocking/warning) and authorised decisions with validity and evidence                                                                  |
| workers, external_worker_ids, worker_aliases, contact_points, worker_skills, worker_availability, pickup_points | Worker directory; external IDs are strings; contacts are versioned (superseded, never edited)                                                                          |
| travel_parties, travel_party_members                                                                            | Private travel arrangements (`additional_passengers_allowed`)                                                                                                          |
| conversations, source_messages                                                                                  | Original evidence: raw text exactly as received, sender, received time, kind (pasted, phone note, email)                                                               |
| orders, order_lines                                                                                             | Header and independently fulfilable shift lines (requested, accepted, minimum counts; local and resolved times; `line_version`)                                        |
| order_revisions, order_source_links                                                                             | Immutable snapshots with changes, reason, actor and linked sources                                                                                                     |
| order_conflicts                                                                                                 | Disagreements between sources; every observed value kept until resolved                                                                                                |
| assignments, assignment_responses                                                                               | Worker on a line with state; every reply kept with the version it answered and its outcome                                                                             |
| resource_reservations                                                                                           | Time reservations for workers, drivers and vehicles (exclusion constraint)                                                                                             |
| drivers, vehicles                                                                                               | Explicit driving capability and willingness; passenger capacity (null = unknown)                                                                                       |
| trips, trip_revisions, trip_stops, trip_passengers, trip_acceptances                                            | Journeys with immutable route/manifest revisions and driver answers per revision                                                                                       |
| transport_requirements                                                                                          | Per assignment and leg: agency trip, private (confirmed), not required, or unresolved (with accountable owner)                                                         |
| tasks, cases, handover_snapshots                                                                                | Owned work with recorded outcomes; exceptions with restricted notes; handovers with acknowledgement                                                                    |
| message_drafts                                                                                                  | Revision-bound messages, recipient contact snapshot and delivery/acknowledgement states                                                                                |
| external_bookings                                                                                               | JoinedUp entry/verification queue per assignment                                                                                                                       |
| outbox_events, audit_events, idempotency_keys, integration_settings, reference_sequences                        | Reliability, audit, request de-duplication, integration status, human-readable references                                                                              |
| worker_heartbeats (migration 0002)                                                                              | Worker liveness for monitoring                                                                                                                                         |
| break_policies (migration 0003)                                                                                 | Versioned break rules per client or site: unpaid minutes after a threshold, paid minutes, agreement reference, effective dates                                         |
| timesheet_batches                                                                                               | One timesheet as received (linked `source_messages` row of kind `timesheet`), supervisor, state submitted/approved/disputed                                            |
| attendance_segments                                                                                             | Hours per person and timesheet: name as written, matched worker, local and resolved times, break basis, paid minutes; revisions with one current row per `segment_key` |
| attendance_approvals                                                                                            | Approve/dispute decisions with the exact segment revisions and checks they covered                                                                                     |
| export_batches, export_rows                                                                                     | Immutable payroll CSV files with checksum and manual import acknowledgement; one `hours` and at most one `reversal` row per segment revision                           |
